# Repository collaboration

Read [CONTRIBUTING.md](CONTRIBUTING.md). Before new implementation, find or create
the GitHub issue, claim ownership, and record the branch/worktree and overlapping
surfaces. Do not duplicate claimed work. Keep dependencies and progress visible.
Link validation and the final commit/PR before closing an issue.

Use isolated issue branches/worktrees for parallel agents. Coordinate shared
contracts and generated files through one owner. Use `devbox` and `just` for tasks.
Keep credentials and original/prepared media outside Git. Simulated browser tests
do not establish live-model accuracy; report live verification separately.
